## ⚠️ 경로 지정 WAF 예외가 이제 경로 경계에서 멈춥니다 — 동작이 바뀝니다

CRS 규칙을 특정 경로에서만 끄셨다면, **지정하지 않은 경로에서도 규칙이 꺼져 있었습니다.**

`/api`로 예외를 지정하면 내부적으로 "이 글자들로 시작하는 모든 주소"로 해석돼서, `/api-admin`·`/apikeys`·`/apiv2/users`까지 규칙이 적용되지 않았습니다. 화면에는 예외가 `/api` 하나로만 보이므로 알아차릴 방법이 없었습니다.

실제 측정 결과입니다. SQL 인젝션 페이로드를 보냈을 때:

| 요청 | 이전 | 이번 버전 |
|------|------|-----------|
| `/api/x` | 통과 (의도됨) | 통과 (의도됨) |
| `/api` | 통과 (의도됨) | 통과 (의도됨) |
| **`/api-admin`** | **통과 ⚠️** | **차단 ✅** |
| **`/apikeys`** | **통과 ⚠️** | **차단 ✅** |
| **`/apiv2/users`** | **통과 ⚠️** | **차단 ✅** |
| `/other` | 차단 | 차단 |

### 업그레이드 전에 확인해 주세요

**지금 오탐이 나던 경로가 사실은 그 "형제 경로"였다면, 업그레이드 후 그 경로에서 다시 차단이 발생합니다.**

- 기존 예외 목록은 **WAF → 호스트별 정책**에서 확인하실 수 있습니다.
- 다시 차단이 생기면 로그에 해당 경로와 규칙 번호가 그대로 남습니다. 로그 상세에서 그 요청을 열면 경로가 자동으로 채워지므로, 예외를 하나 더 추가하시면 됩니다.
- `/api/`처럼 슬래시로 끝나게 적으셨어도 `/api`와 똑같이 동작하며 `/api/x`도 계속 면제됩니다.
- 예전 버전에서 범위를 `/`로 저장하신 예외는 **기존과 동일하게 호스트 전체 면제로 유지**됩니다. 갑자기 좁아지지 않습니다.

이 변경은 **프록시 컨테이너가 재시작될 때** 적용되며, 이미지 업그레이드가 재시작을 수행합니다.

## ⚠️ Path-scoped WAF exclusions now stop at a path boundary — this changes behaviour

If you switched a CRS rule off for one path, **it was also switched off on paths you never named.**

An exclusion scoped to `/api` was matched as "any address starting with these bytes", so `/api-admin`, `/apikeys` and `/apiv2/users` lost the rule too. The screen showed a single exemption for `/api`, so there was no way to notice.

Measured, sending a SQL injection payload:

| Request | Before | This release |
|---------|--------|--------------|
| `/api/x` | passed (intended) | passed (intended) |
| `/api` | passed (intended) | passed (intended) |
| **`/api-admin`** | **passed ⚠️** | **blocked ✅** |
| **`/apikeys`** | **passed ⚠️** | **blocked ✅** |
| **`/apiv2/users`** | **passed ⚠️** | **blocked ✅** |
| `/other` | blocked | blocked |

### Check before upgrading

**If the false positive you were suppressing actually sits on one of those sibling paths, it will start being blocked again after this upgrade.**

- Review your exclusions under **WAF → per-host policy**.
- A returning block is loud: the log names the path and the rule. Open that request in the log viewer and the path is prefilled — adding a second exclusion is two clicks.
- A scope typed with a trailing slash (`/api/`) is treated as `/api` and still exempts `/api/x`.
- An exclusion stored by an older version with a scope of `/` **keeps behaving as a host-wide exemption**. It does not silently narrow.

The change takes effect when the proxy container restarts, which the upgrade performs.

## 🧰 Internal quality (no user impact)

Four long-standing test failures turned out to be defects in the tests themselves. The product was fine, but the red results sat in every pre-release run where they could hide a real regression.

- The global settings save test was clicking **"Apply recommended" instead of Save** — 19 tests were passing while saving nothing.
- Three proxy host form tests mistook the loading spinner for the form and failed every run.
- `npm run lint` had been failing on 3 errors.
- **CI now runs tests and lint on every push.** Until now checks only ran when a tag was cut, which is why the above went unnoticed for months.
