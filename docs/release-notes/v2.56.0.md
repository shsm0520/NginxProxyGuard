## 🔓 차단 해제가 실제로 풀리지 않던 문제

**IP 차단을 해제했는데 계속 차단되던 증상이 있었습니다.** 화면에서는 목록에서 사라지고 DB에서도 지워지는데, nginx는 그 IP에 계속 403을 돌려줬습니다.

원인은 캐시였습니다. 해제 직후 NPG가 스스로 설정을 다시 생성하는데, 그때 **지우기 전의 낡은 차단 목록**을 읽어서 방금 해제한 주소를 설정 파일에 다시 써 넣었습니다. 설정 파일에 박혀버린 뒤로는 캐시가 만료돼도 저절로 풀리지 않습니다 — 다른 호스트를 저장하거나 "전체 동기화"를 누르거나 재시작할 때까지 계속 차단된 상태로 남습니다.

**여러 개를 한 번에 해제할 때 특히 잘 나타납니다.** 목록에서 여러 개 선택 후 해제하거나 "전체 해제"를 쓰는 경우입니다.

실제로 측정한 결과입니다. 해제 직후 생성된 nginx 설정을 확인했습니다:

| 해제 후 | 이전 | 이번 버전 |
|---|---|---|
| DB의 차단 기록 | 삭제됨 | 삭제됨 |
| 내부 캐시 | **남아 있음** | 삭제됨 ✅ |
| **nginx 설정에 남은 차단** | **남아 있음 — 계속 차단** | 없음 ✅ |

## 🔒 차단이 조용히 풀리던 문제

이미 차단된 IP를 **다시 차단하거나 기간을 연장하는 도중 브라우저 탭을 닫으면, 기존 차단이 사라졌습니다.**

내부적으로 "기존 기록 삭제 → 새 기록 추가" 두 단계로 처리하던 탓에, 그 사이에 요청이 끊기면 삭제만 되고 추가는 안 되는 상태가 됐습니다. 요청 시간 초과나 DB 연결이 끊길 때도 마찬가지였습니다.

이제 한 번의 작업으로 처리합니다. 재밴 요청을 40회 중간에 끊어 측정했을 때 **이전에는 2건에서 차단이 사라졌고, 이번 버전에서는 0건**입니다.

## 🛡️ WAF 자동 차단 기간이 음수일 때

`WAF 자동 차단 기간`에 음수가 들어가면 차단이 **만들어지자마자 이미 만료된 상태**가 되어 어떤 설정에도 반영되지 않았고, 같은 공격자가 임계치를 넘을 때마다 차단·알림·전체 설정 재적용이 무한히 반복됐습니다. 이제 예전처럼 영구 차단으로 처리합니다.

## 🗺️ 세계 지도 라이브러리 업그레이드

대시보드의 국가별 접속 지도가 쓰는 라이브러리를 올리면서, 마우스를 올렸을 때의 강조·커서·툴팁이 사라지지 않도록 함께 이전했습니다. 보이는 동작은 이전과 같습니다.

## 🔑 SSO 로그인이 실패하던 경우 (해당 환경만)

인증 서버(IdP)가 공개하는 키 목록에 NPG가 읽지 못하는 키가 **하나라도** 섞여 있으면, 나머지 키가 멀쩡해도 **모든 SSO 로그인이 실패**했습니다. 라이브러리 업데이트로 해당 키만 건너뛰도록 바뀌었습니다. 대부분의 IdP는 영향이 없지만, v2.35.0부터 이 버전 전까지 계속 있던 문제입니다.

## 🔓 Unbanning an IP did not always unban it

**You could remove a ban and still be blocked.** The entry disappeared from the list and from the database, but nginx kept answering 403 for that address.

The cause was a cache. The unban triggers its own config regeneration, and that regeneration read the **pre-delete ban list**, writing the address you had just removed back into the generated config. Once it is in the config file it does not clear itself when the cache expires — the client stays blocked until something unrelated regenerates that host: saving another host, a "Sync All", or an API restart.

**Unbanning several at once is the likely case** — a multi-select unban, or "Unban all".

Measured by looking at the generated nginx config right after the unban:

| after unbanning | before | this release |
|---|---|---|
| database row | deleted | deleted |
| internal cache | **survived** | deleted ✅ |
| **address still in the nginx config** | **still there — still blocked** | gone ✅ |

## 🔒 A ban could be lifted silently

**Re-banning or extending an already-banned IP and closing the browser tab mid-request removed the existing ban.**

The write was two steps — delete the old record, then insert the new one — so a request that stopped in between left only the delete. A statement timeout or a dropped database connection did the same.

It is now a single operation. Cancelling 40 re-ban requests mid-flight: **2 of 40 lost the ban before, 0 of 40 now.**

## 🛡️ Negative WAF auto-ban durations

A negative `WAF auto-ban duration` produced a ban that was **already expired the moment it was written**, so it reached no config at all, and the same attacker re-triggered the ban, the notification and a full config reload on every threshold crossing. It is treated as a permanent ban again, as it was before.

## 🗺️ World map library upgrade

The dashboard's country map moved to a new major version of its rendering library, with the hover highlight, cursor and tooltip migrated so they keep working. Nothing changes visually.

## 🔑 SSO logins failing (affected setups only)

If your identity provider published a key set containing **even one** key NPG could not parse, every SSO login failed, regardless of the other keys being fine. A library update makes it skip that key instead. Most providers are unaffected, but the defect had been present since v2.35.0.
